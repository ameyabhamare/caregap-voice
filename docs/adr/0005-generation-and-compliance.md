# 5. Script generation, prompt registry and rule-based compliance

Date: 2026-10-22. Status: Accepted.

## Context
Outreach scripts are generated by an LLM and read aloud to health plan members. They must
carry a disclaimer and an opt-out, must not leak personal health information, must not
name diagnoses or drugs, and must be short enough to speak. Generation must run on a free
local model by default, with Claude available behind a hard budget cap, and every change
to a prompt must be traceable.

## Decision
- **One provider interface, metered.** `LLMProvider` implementations (Ollama, Claude) do
  raw calls only. `LLMClient` wraps a provider with the cost ledger, so every runtime call
  goes through `CostLedger.guard`. Ollama is the default; Claude is selected with
  `LLM_PROVIDER=claude`.
- **Claude specifics.** Default model `claude-opus-5-5` with `output_config.effort`
  (default `medium`). No sampling parameters (current models reject them). Server-side
  refusal fallbacks (`fallbacks="default"`) are on; if another model served a call, the
  ledger charges the higher price. Thinking tokens bill as output, so script calls get a
  4,000-token ceiling on Claude versus 600 on Ollama.
- **Prompts.** YAML files in `prompts/` are the source of truth. `make prompts-register`
  registers a new MLflow prompt version only when the text changed and moves the
  `production` alias; the service loads by alias, so a bad version can be rolled back in
  MLflow without a deploy. Prompt versions are stored with every script and eval run.
- **PHI minimisation at the input.** Only allowlisted member fields (first name) and
  plain service descriptions reach the model. Diagnoses, drugs, dates and identifiers
  are never in the prompt, so the model can only leak them by inventing them.
- **Rule-based compliance at the output.** Deterministic checks: verbatim disclaimer and
  opt-out (case, spacing and punctuation-insensitive), word limit, member PHI (last name,
  birth date, age, phone, member ID), date/phone/ID patterns, diagnosis terms, drug names,
  unfilled placeholders. No model is involved, so the checks are fast, explainable and
  usable in CI.
- **Revise once, then a human.** A failed script is sent back once with the specific
  violations. A second failure is stored as `needs_review` and appears in the review
  queue (`GET /reviews`, `POST /reviews/{id}`).
- **One script per member**, covering up to two open gaps in a fixed measure order.
- **Outreach profile.** Plan name, disclaimer, opt-out, limits and wording live in an
  `OutreachProfile`. Phase 3 ships one built-in default; Phase 6 loads per-customer YAML
  of the same shape.

## Consequences
- Requiring the model to reproduce the disclaimer verbatim is strict; small local models
  may paraphrase it. That is measured by the rule eval rather than hidden by inserting the
  text deterministically. Inserting fixed text in code is a candidate change for Phase 8's
  prompt iteration, where it can be compared on the same eval.
- Keyword rules catch named diagnoses and drugs, not every possible disclosure (e.g. a
  paraphrase like "your blood sugar condition"). The LLM-as-a-judge in Phase 8 adds a
  semantic check on top.
